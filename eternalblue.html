    Byte-Sized Breaches · Case file 01 · 2017

    EternalBlue

    In 2017, one miscounted number deep inside Windows let a leaked spy tool lock up hospitals, car factories and more than 200,000 computers in a few days.

    This is how it worked, told as a story with small games along the way. You don't need to know anything about computers.

    Chapter 1 · The mailroom

    Every Windows computer has a mailroom

    When computers in an office share files or printers, they send each other little requests. Can I have the budget spreadsheet? Please print this.

    On Windows, the part that handles those requests is called SMB. Picture a mailroom clerk behind a hatch numbered 445, waiting for packages from other computers.

    Send the clerk a few packages and see how the mailroom works.

    The clerk opens some kinds of packages without asking who sent them. An attacker doesn't need a password to start talking to the mailroom.

    Master keys

    See the keys on the clerk's belt? The clerk carries the master keys to the whole building. Whatever the clerk does, it does with full control of the computer. Techies call this level the kernel.

    Go deeper · What SMB really is

    SMB stands for Server Message Block. It's how Windows computers share files and printers, and its first version dates from the 1980s.

    In 2017 the old version, SMBv1, was still switched on in most Windows computers, even though newer versions existed.

    It listens on network port 445. A port is like a numbered door on a computer: different services wait behind different numbers.

    Windows handles SMBv1 in a driver called srv.sys, which runs inside the kernel, the most powerful part of the system. A bug there means total control.

    EternalBlue didn't need a username or password. It connected with an anonymous login, known as a "null session".

    Chapter 2 · The bug

    A stamp with one digit missing

    Some packages carry an old-style packing list, in a format from the early 1990s. Before filing it, the clerk translates it into the modern format.

    First the clerk checks how long the list is. If there's junk at the end, the clerk crosses it out and stamps the corrected length onto the label.

    Here's the bug. The label has room for five digits, but the clerk's correction stamp only has four. The first digit never changes.

      Go deeper · The real numbers

      The "packing list" is a list of file extended attributes: small labels attached to files, sent here in the old OS/2 format. Translating it is the job of a function in srv.sys called SrvOs2FeaListToNt.

      The list's length is stored as a 32-bit number. The code that corrects it, SrvOs2FeaListSizeToNt, writes back only a 16-bit number, so only the bottom half changes. Computers count in hexadecimal here, but the effect is exactly like the stamp above.

      EternalBlue sends a list that claims to be 0x10000 bytes long (65,536). After the "correction" it claims 0x1FF5D instead of 0xFF5D: about 64 KB more than Windows set aside.

      Two smaller bugs helped. One let the attacker send a list big enough to need that fifth digit, by starting a request as one kind of transaction and finishing it as another. The other let them reserve a block of memory of a size they chose, which comes in handy in the next chapter.

      Microsoft tracks the main flaw as CVE-2017-0144 and fixed it in update MS17-010.

      Chapter 3 · The spill

      Spilling onto the next desk

      Writing past the end of the space you set aside is called a buffer overflow. The extra entries spill out of the tray onto whatever sits next to it in the computer's memory.

      Usually that just crashes the computer, and Windows shows its famous blue error screen. But if the attacker can choose what sits next to the tray, the spill becomes a weapon.

      Some desks hold an instruction card that tells the clerk what to do next. Arrange the desks so the spill lands on one of your cards.

      The attacker now holds the master keys

      The clerk reads the overwritten card and follows it straight into the attacker's own instructions. Because the clerk carries the master keys, the attacker now controls the whole computer. No password. Nobody clicked anything.

      EternalBlue then installed a hidden back door called DoublePulsar. It ignores normal visitors and answers only a secret knock. Try both.

      Go deeper · Grooming the heap

      The desks are chunks of kernel memory called the non-paged pool. The attacker opens many connections at once, and each one makes Windows reserve a buffer (an "srvnet buffer") in a predictable spot. Arranging memory like this is called heap grooming, or "heap feng shui".

      Then the attacker frees one slot, so the overflowing buffer lands in that gap, right in front of one of the attacker's own buffers.

      The spill overwrites the start of that neighbouring buffer, including a pointer that says where incoming network data should be stored. It points at a memory address that was fixed and predictable on older Windows versions. The attacker's next message gets written there, and Windows ends up running it as code with full kernel power.

      It didn't always work. When the layout went wrong the machine crashed, which is why many Windows XP computers hit by WannaCry showed a blue screen instead of a ransom note.

      DoublePulsar hid inside one of SMB's own commands. Defenders later scanned for it by sending that command and looking for its tell-tale reply.

      Chapter 4 · The leak

      A spy tool gets loose

      Ordinary criminals didn't find this bug. EternalBlue came from the US National Security Agency (NSA), which had kept the flaw secret instead of reporting it to Microsoft.

      In 2016, a mysterious group calling itself the Shadow Brokers started leaking hacking tools it said were stolen from an NSA-linked team. On 14 April 2017 it posted EternalBlue online for anyone to download.

      One month earlier, on 14 March 2017, Microsoft had released a fix called MS17-010. The cure was out before the weapon. The only question was whether people had installed it.

      Go deeper · Patches, leaks and missiles

      Microsoft skipped its usual February 2017 update day, which was unusual. The March update, MS17-010, fixed six SMBv1 bugs (CVE-2017-0143 to CVE-2017-0148). Reports later said the NSA had warned Microsoft once it realised its tools had been stolen.

      The leak included other tools with similar names, such as EternalRomance, EternalChampion and EternalSynergy, plus the DoublePulsar back door.

      Windows XP had stopped getting updates in April 2014. After WannaCry, Microsoft took the rare step of releasing a fix for it anyway.

      Microsoft's president, Brad Smith, compared the leak to "the U.S. military having some of its Tomahawk missiles stolen", and called on governments to report flaws instead of stockpiling them.

      Chapter 5 · Outbreak

      WannaCry: a worm that knocks on every door

      On Friday 12 May 2017, a program called WannaCry started spreading. It was ransomware: it scrambled (encrypted) people's files and demanded $300 in Bitcoin to unscramble them, rising to $600 after three days.

      What made it so fast was EternalBlue. WannaCry was a worm: every infected computer looked for other computers with door 445 open, broke in with EternalBlue, and started looking again. Nobody had to click anything.

      Go deeper · Inside WannaCry

      WannaCry scanned its own local network and random internet addresses for port 445. When it found an open door, it checked for the DoublePulsar back door, broke in with EternalBlue if needed, then used the back door to copy itself across.

      It encrypted files with strong encryption (AES for the files, with the keys locked by RSA), so there was no shortcut to unlock them without the attackers' key.

      Paying rarely helped. Only about $140,000 in Bitcoin was paid in total, and the attackers had no reliable way to tell which victim had paid.

      In December 2017 the UK and US governments publicly blamed North Korea, pointing to a hacking group often called Lazarus.

      The simulation is a simplification. Real worms keep scanning until the machine is cleaned or switched off, and real networks have many more ways in and out.

      Chapter 6 · The kill switch

      The $10.69 off switch

      Within hours, security researchers were taking WannaCry apart. A 22-year-old British researcher, Marcus Hutchins, noticed something odd: before doing anything else, WannaCry tried to visit a long, nonsense web address that nobody owned.

      He registered the address himself, mainly to track the infection. It turned out to be an off switch. Run WannaCry once to see the outbreak, then find the switch in its steps and try again.

      Go deeper · Why was there a switch?

      Hutchins wrote up what happened on his blog, MalwareTech. He registered the address to count infections, and only realised afterwards that doing so had switched the worm off.

      Already-encrypted computers stayed locked. The switch only stopped new infections from going further.

      A popular theory is that the check was meant to spot security researchers' test machines, which often pretend every web address exists. Nobody outside the group behind WannaCry knows for sure.

      Within days, copycat versions with different switches, or none, appeared. By then many organisations had installed the fix.

      Chapter 7 · The sequel

      Six weeks later: NotPetya

      On 27 June 2017, a second attack used EternalBlue, and it was worse. NotPetya looked like ransomware, but its "unlock" process could never work. It was built to destroy.

      It started in a hacked update for M.E.Doc, accounting software used by many companies in Ukraine. Then it spread with EternalBlue and a second trick: stealing passwords from memory and using them to log into other computers. That trick even worked on computers that had the March fix.

      Shipping giant Maersk, which carries close to a fifth of the world's shipping, lost almost its entire network. Here's how it got back.

      Go deeper · How NotPetya worked

      NotPetya was named after an older ransomware called Petya, which it resembled. Researchers soon found it was really a wiper: the ID it showed victims for "unlocking" was random, so even paying couldn't bring files back.

      It spread with EternalBlue and EternalRomance, plus Mimikatz, a tool that pulls passwords out of a computer's memory. With those passwords it used Windows' own admin tools (PsExec and WMI) to log into other machines, including fully patched ones.

      It overwrote the start of the hard drive (the master boot record) and encrypted the file table, so infected computers couldn't even start up.

      Maersk rebuilt about 4,000 servers and 45,000 PCs in roughly ten days, and put the cost at up to $300 million. Total damage worldwide was estimated at about $10 billion, making NotPetya one of the most expensive cyberattacks ever. In February 2018 the UK and US governments blamed the Russian military.

      Your defences

      At home

      • Leave automatic updates on, and restart when your computer asks.
      • If your computer no longer gets security updates (Windows XP, Windows 7, and Windows 10 since October 2025), plan to upgrade.
      • Keep a backup on a drive you unplug, or in a cloud service that keeps old versions.
      • If ransomware hits, don't pay. Disconnect the device and report it to the police or your national cybercrime unit.

      At work

      • Patch fast, especially bugs that let attackers in without a password.
      • Switch off SMBv1 and never expose port 445 to the internet.
      • Split the network into zones and limit where admin accounts can log in.
      • Keep offline backups, and practise restoring from them.
      • Keep a list of every device, including the old ones nobody remembers.
      Go deeper · The defences in detail

      MS17-010 is the fix for this bug. Microsoft's bulletin lists the update for each Windows version.

      Microsoft recommends switching SMBv1 off. Since late 2017 (Windows 10 version 1709), new Windows installations leave it out by default.

      Port 445 should almost never be reachable from the internet. Block it at the edge of the network.

      Segmentation splits a network into zones so a problem in one can't spread freely to the others. Limiting admin accounts stops tricks like NotPetya's stolen passwords from unlocking everything.

      Offline backups are copies kept disconnected from the network, out of the malware's reach. A backup only counts if you've tested restoring from it.
